# 产品规格

## 用户与场景

主要用户是参加 CUMCM 的本科生队伍和日常训练者。典型场景包括：导入题目与附件、在人工检查点确认题意和假设、运行可复现实验、生成有证据的论文草稿、检查提交 PDF。

## 输入与输出

输入包括 PDF、图片、Word、Excel、CSV、文本和用户决策。长期输出包括代码、结果、图表、表格、引用、验证报告、LaTeX 源文件和最终 PDF。所有输出归属于单个 workspace。

## 可测试需求

- 初始化不得覆盖已有重要文件；重复初始化返回已存在清单。
- 状态命令不得写入 workspace。
- 所有核心路径必须是 workspace 相对路径并拒绝路径穿越。
- 每个实验必须记录输入哈希、参数、随机种子、环境、命令、时间、状态和产物。
- 复杂模型必须关联 baseline 与模型选择证据。
- 写作阶段只能消费已验证的结构化结果。
- PDF 只有在编译、格式、视觉和身份泄露检查均通过时才能进入 `FINALIZED`。
- assisted 模式必须在题意、假设、模型和定稿处留下决策记录。

## 非功能需求

- Python 3.11+；Windows 11 与 macOS；路径跨平台。
- 中断后从最近完成阶段恢复；阶段输出具有确定位置和明确 schema。
- 错误信息包含文件、字段和修复方向；失败不得破坏已有产物。
- 默认最小权限，不修改系统配置，不静默安装外部软件。

## 明确不做

第一阶段不做自动读题、联网研究、模型推荐、代码生成、论文生成、LaTeX 模板实现、PDF 视觉验收、API/RAG/Web UI/数据库/Docker、多 Agent 或 GPU 训练。

第二阶段仍不做自动读题、模型推荐、代码生成、联网研究或完整论文生成；只对一个公开标记为 synthetic 的固定工程示例建立真实执行、验证、报告和编译门禁。

## MVP 验收

四个 CLI 命令可运行；数据模型可导入；example workspace 通过验证；损坏 YAML 与缺失目录返回非零退出码；benchmark 与 2026 provisional 规范可被人工审阅；测试在 Windows 路径语义下通过。

## 风险

主要风险是赛题理解错误、结果幻觉、模板过期、身份泄露、依赖环境差异和上游许可证冲突。缓解措施见 `risk_register.md`。
